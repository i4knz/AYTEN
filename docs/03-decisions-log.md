القرارات التي اتُّخذت أثناء التنفيذ ولم تُعتمد بعد، مع سبب كل منها. أي قرار يمكن الرجوع عنه بتكلفة معروفة.

| # | القرار | البديل الذي كان في الخطة | السبب | تكلفة الرجوع عنه |
|---|--------|---------------------------|------|------------------|
| D1 | استخدام الافتراضات الأولية (Next.js + TypeScript + PostgreSQL، مجلد `platform/`، الاسم الرمزي Ayten Commerce) قبل وصول إجابات أسئلة الوثيقة 01 §9 | انتظار الإجابات | طلب المؤسس «ابدأ التنفيذ» | الاسم: تعديل نصوص. الحزمة: مرتفعة بعد أسبوعين من البناء — **يلزم الحسم الآن** |
| D2 | مصادقة مكتوبة داخلياً بأدوات معيارية (Argon2id عبر `@node-rs/argon2`، رموز عشوائية 256-bit، تخزين الـ hash فقط، جلسات في PostgreSQL) بدلاً من مكتبة Better Auth | Better Auth | تحكم كامل في مخطط البيانات وتكامله مع RLS وسجل التدقيق؛ اختبار مباشر لكل مسار؛ عدم الاعتماد على واجهات مكتبة قد تتغير. **المخاطرة:** كود أمني نملكه ونصونه — يُعوَّض بالاختبارات ومراجعة أمنية خارجية قبل الإطلاق العام | متوسطة: الكود محصور في `src/server/auth/` |

| D4 | الترحيلات بـ SQL مكتوب يدوياً + مشغّل بسيط يتحقق بـ checksum، وDrizzle للاستعلامات فقط (دون drizzle-kit) | drizzle-kit | سياسات RLS والدوال والمشغلات أوضح وأدق بـ SQL مباشرة | منخفضة |

| D7 | رسالة «البريد مسجل مسبقاً» صريحة عند التسجيل، مع تحديد معدل التسجيل لكل IP | رسالة عامة | وضوح التجربة أهم هنا؛ الاستعادة والدخول لا يكشفان وجود الحساب | منخفضة |

## ما لم يُنفَّذ بعد من خطة الأسبوع الأول

- دعوة الموظفين وقبول الدعوة (اليوم 6) — الصلاحيات جاهزة ومختبرة، الواجهة وجدول الدعوات لم يُبنيا.
- النشر على بيئة staging والمراقبة (Sentry) والنسخ الاحتياطي (اليوم 7) — تحتاج قرار الاستضافة والنطاق.
- سياسة أمان المحتوى (CSP) بـ nonce — مطلوبة قبل الإطلاق.
- رفع الشعار — يحتاج تخزين الكائنات (S3) ويأتي مع رفع صور المنتجات.
